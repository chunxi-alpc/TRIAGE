## 1. 为什么需要这一轮

上一轮 MEGA-CDP `train_val` 有 **40 对、80 例、36 个指南**，按开发集选择的共同偏置强度为 \(\beta=2\)：

| 已完成方法 | 正确决策 | 反事实成对正确 | 不适用目标规则的误用 |
| --- | ---: | ---: | ---: |
| B0：原始完整指南提示 | 64/80 | 29/40 | 4/40 |
| B2：固定增强动作和支持证据 | 64/80 | 29/40 | 3/40 |
| B3：预测适用性后切换目标 | 64/80 | 29/40 | 3/40 |
| B6：使用全部参考关系的 ACRE | 66/80 | 30/40 | 3/40 |

已知问题：

- 目标规则适用性准确 **60/80（75%）**；目标规则不适用却被预测为适用 **12/40（30%）**。
- **25/80** 例出现多个被预测为适用、但动作冲突的规则，导致正常增强关闭。
- B2 和 B3 的三个主要离散指标相同；但不能据此判断两者所有增强掩码、概率或逐例动作相同。
- B6 比 B3 高 **2/80**，但 **B6 同时替换了相关性、适用性和证据**，不能把差值归因为适用性，也不能判断“切换”优于“固定增强”。
- 另有“只替换正确适用性”的诊断达到 **67/80**，但没有相应的**正确适用性 + 固定增强**对照。
- **37/40 对**为资源、可用性或实施条件；没有独立临床专家盲审、未知真值样本和独立测试。

因此要将两个问题解耦：

1. **核心方法问题**：给定相同且正确的规则相关性、适用性和证据，*固定增强*与*按适用性切换*哪个更好？
2. **上游问题**：如果正确标注下切换有效，预测标注的哪些错误使收益消失？

不能在没有解决第一个问题之前，反复优化自标注提示以寻找开发集正结果。

## 2. 本轮锁定条件与防泄漏要求

- 使用现有冻结的 **40 对、80 例**开发集，不重新筛选、丢弃或替换样本；现有 24 例历史诊断只作回归检查。
- **只用 Qwen3-8B**，复用现有模型权重、分词器、聊天模板、完整指南、患者记录、问题及同一候选动作集合；保持固定单词元选择协议。
- 使用现有 `AttentionBias`，**所有层／所有头、最后的决策查询位置，统一加性 logit 偏置**；不增加选头、谱投影、训练或其他算子。
- 预先固定主要 \(\beta=2\)，附加敏感性检查 \(\beta=1\)，\(\beta=0\) 仅验证恒等性。**不得根据本轮结果扩大网格或重新选 \(\beta\)**。
- 所有同一来源的比较共享相同的规则相关性、证据跨度、提示、候选动作和 \(\beta\)，**唯一改变选目标的策略**。
- **参考关系只在明确标为 Oracle 的诊断运行中用于生成掩码**，不得进入普通 B0/B2/B3 的提示、缓存、自标注或任何可部署版本；Oracle 的结果一律标注“不可部署的诊断对照”。
- 本批开发样本已经被观察并用于选 \(\beta\)，因此所有差异、置信区间和显著性检验均属**探索性**，不能宣称独立证据。
- 动作误用沿用此前[动作同义表达审计](../../results/acre_pilot/round2/action_alias_audit.json)的冻结判定；如再发现错误，记录事后修订并保存旧计数，不能只修正有利于新方法的样本。
- **不更改原来的 B0–B6 定义与旧结果**，新对照使用新命名、新输出路径。

## 3. E0：不调用模型的增强目标与错误审计（首先完成）

使用 `case_results.jsonl.gz`、`annotations.jsonl.gz` 与同一病例的离线参考文件，逐例重建旧 B2、B3 的**实际最终合并 key token 集合**，不能只看单条目标规则选择。

记 \(\mathcal S_{2,x}\)、\(\mathcal S_{3,x}\) 为病例 \(x\) 在共同 \(\beta=2\) 下**真正进入偏置算子**的 token 位置，记录：

\[
\left|\mathcal S_{2,x}\right|,\quad
\left|\mathcal S_{3,x}\right|,\quad
\left|\mathcal S_{2,x}\triangle\mathcal S_{3,x}\right|,\quad
\operatorname{Jaccard}(\mathcal S_{2,x},\mathcal S_{3,x}).
\]

两个集合皆空时 Jaccard 记为“不适用”，不要定义为 1 后当作有效切换。

逐例分类：

1. 两种掩码完全相同。
2. 一方非空，另一方为空。
3. 两方非空且掩码不同（**真正的非零对照**）。
4. 因多条预测适用规则动作冲突，统一关闭增强。
5. 映射／证据不可用或其他原因未增强。

此外，单独审计：目标规则真实适用性、模型预测适用性、预测相关性、所选证据的角色与位置，以及原始和增强后的最终预测是否不同。对真正切换者，要求能明确指出**哪些动作 token 被移出、哪些否定证据／例外 token 被移入**；防止将仅“删除部分增强”描述成有效否定证据增强。

**E0 输出**：`mask_audit.csv`、`mask_audit_summary.json`、`annotation_error_audit.csv`。

**验收**：80 例全覆盖，旧 B2/B3 掩码与历史保存位置一致，逐例可重算；若不一致，先修复审计逻辑，停止后续 GPU 实验。必须同时报告全样本与“掩码真正不同”的子集大小，不能只分析成功案例。

## 4. E1：核心实验——正确标注下的固定增强 vs 条件化增强

**本轮最高优先级。它验证的不是新版模块一，而是 ACRE 唯一拟主张的方法贡献。**

构造以下同源 Oracle 对照。两方都使用**完全相同**的参考相关性、参考适用性、原文动作、支持／否定证据及例外信息；不能像上一轮 B2（预测信息）与 B6（参考信息）那样混合来源。

| 方法 | 关系与证据来源 | 增强策略 | 用途 |
| --- | --- | --- | --- |
| O0 | 不使用标注 | 无增强（复用 B0） | 同一决策输入的基础性能 |
| **OF** | 同一套参考关系与证据 | **始终增强动作 + 支持证据** | 正确标注下的固定增强 |
| **OS** | 与 OF 完全相同 | **适用：动作 + 支持证据；不适用：否定证据 + 例外；未知：空集合** | 正确标注下的目标切换 |
| OP | 与 OF/OS 相同（可选） | 相同参考标注直接写入提示、无注意力修改 | 上游答案信息量参照，仅可选诊断 |

具体要求：

- **主对照使用完整的参考规则集合**，按同一参考协议生成 OF 和 OS。若 OS 实际与旧 B6 相同，应通过重算确认掩码和 logits 一致，再复用旧 B6；不许无理由重新跑已有结果。
- 为排查“多规则合并覆盖”，可附加一个**仅参考目标规则**的受控版本：在同一离线参考目标规则上同时运行 OF-target 和 OS-target。参考目标规则来自评估数据，**是高度知晓答案的 Oracle 诊断**，只能用来隔离因果对照，不能作为部署算法或主准确率。
- 对“目标规则真实不适用”的病例，OF 仍按固定策略强调该规则的动作与已有支持证据；OS 只强调有证据支持的否定条件／例外片段。所有候选动作仍保留在决策提示中。
- 两组目标必须从**同一个参考表示**转换到词元位置；禁止 OF 使用预测证据、OS 使用参考证据；禁止把参考状态的文字直接写入任何一组决策提示。
- 如果 OS 的否定证据因其他规则合并后已经在 OF 中被增强，须记录合并后的实际效果；不强行删去其他规则掩码后宣称目标切换有效。
- 对 OF、OS 使用共同 \(\beta=2\)（主结果）；\(\beta=1\) 仅作事先固定的敏感性报告。报告 \(\beta=0\) 恒等性。
- **给出显式的 OF vs OS 逐例预测变化、目标差异、正向与负向行为改变**。若二者掩码一致或均为空，此类病例只属于覆盖率口径，不构成实际目标切换证据。

**核心判定**：如果有足够病例真正增强了不同的目标，而 OS 对 OF 没有方向一致的正确决策边际改善、减少误用或净行为收益，那么在当前架构下“切换增强目标”尚未得到支持；不能直接通过提升自标注来解释为核心方法有效。

## 5. E2：仅当 E1 发现正向机制信号时，分析新版模块一

**E2 先做离线归因，不默认重新开发模型自标注器。**

保持 E1 的相同模型和算子，对比四格：

| 标注源 | 固定目标 | 切换目标 |
| --- | --- | --- |
| 模型预测 | B2（已有） | B3（已有） |
| 全部参考关系／证据 | **OF（新增）** | **OS（新增／复用 B6）** |

以相同样本、同一竞争动作、同一 \(\beta\) 比较行为指标与决策边际。两行之间的信息量不同，但**行内 OF vs OS 和 B2 vs B3 是公平的目标切换对照**；这可检验“上游预测质量是否掩盖切换收益”。

再审计本轮已知上游问题：

- 目标规则 **12/40 不适用误判适用**：分类为否定极性、必要条件／合取关系、时间、数值、实施／资源条件、证据缺失或规则语义不一致等。对每类保存患者原句、源规则条件、模型状态与可验证状态。
- **25/80 多规则预测冲突**：区分真正存在多个动作不兼容的适用规则，与相关性误选、动作同义表达、上游状态误判导致的虚假冲突。使用冻结的动作别名审计，不私自改变指标。
- **74/80 决定性证据召回**：补充证据精确性／是否仅因选择了包含决定句的长段落而得分，区分定位成功与语义判断正确。
- **未知类**：当前无可靠未知真值样本，不能宣称未知检测的敏感度；如需研究未知类，另拟数据方案，不在本轮硬凑。
- 对当前 `source_ids_json_grammar.v3` 的编码规则、证据目录、片段数量限制进行静态检查和明确归因；不以事后调参作为解释。

如果 OF/OS 显示“参考正确标注下的切换确实有效，而预测标注下无效”，再单独提出一个**最小、可归因**的模块一修正建议，并说明需要在**新指南开发集**而非同一 40 对样本上验证。若 OF/OS 都无效，停止针对“提升自标注以证明 ACRE”的优化路线。

**E2 输出**：`factorial_metrics.json`、`annotation_error_categories.csv`、`upstream_bottleneck_analysis.md`。

## 6. E3：长度与目标方向控制（条件触发）

只有当 E0 发现实际差异、E1 显示可能的方向性收益时，才进行额外前向测试。

- **长度控制**：比较 OF/OS 的实际不同目标词元数量；尽可能构造词元数量匹配、语义来源可追溯的无关片段目标。不强行截断决定性证据来达到等长，而把有效词元数、句子数、增强覆盖率作为协变量或分层指标完整报告。
- **非目标对照**：无关片段必须来自相同输入、与正确证据和目标动作不重叠；对每个病例验证**最终合并 token 集合真的发生变化**。上一轮噪声替换没有改变合并目标，不能重复那种无效实验。
- **仅看方向的控制**：以固定的参考正确动作 \(y^*\) 和同一反事实分支的竞争动作 \(y^-\) 计算所有方法的
  \[
  m_\beta(x)=\log P_\beta(y^*\mid x)-\log P_\beta(y^-\mid x),\qquad
  \Delta m=m_\beta-m_0 .
  \]
  比较 OS−OF 的边际，尤其是**目标规则不适用且掩码真正不同**的病例；记录方向正、零、负与其数值，不以注意力质量增加代替决策收益。
- 如果找不到无关片段或掩码不改变，记录为“无效控制／未完成”，不能据此宣称鲁棒性。

## 7. 指标、统计与口径

主报告为 **全部 80 例**，另分层报告目标规则适用 40 例、不适用 40 例、预测状态正确／错误、是否存在冲突关闭、掩码真正不同／未不同：

1. **总体固定选项准确率**：正确数 / 80；逐例记录竞争动作和预测。
2. **适用病例准确率**：正确数 / 40；本轮不称严格 ACF，因为没有新的闭卷冲突标注。
3. **OAR（不适用目标动作误用率）**：使用已审计完整动作别名，误用数 / 40；同义推荐动作必须合并计错，不能仅比较选项标签。
4. **PairAcc（成对准确率）**：一对反事实两个成员都正确的对数 / 40。
5. **原本正确保持率**：分母为已有 B0 正确的 64 例；不得将这一条件下的分母换成各自方法的正确数。
6. **正确—竞争动作决策边际**：全部病例及真正发生目标差异的子组分别报告 \(\Delta m\)、OS−OF、正／零／负数和分布。
7. **增强覆盖率**：非零增强数、目标词元数、掩码交并、被规则冲突关闭数。
8. **对照的成对改变**：只 A 正确、只 B 正确、共同正确、共同错误；不能把相同准确率误认为相同预测。

统计上报告配对 McNemar 检验和以**指南为聚类单位**的 bootstrap 95% 区间，反事实对保持完整；强调**全部是已经用于开发和选择 \(\beta\) 的同一批数据上的探索性检验**。当前 36 个指南下的区间不能证明模型等效或论文效果显著。前述分层分析均用于解释机制，不能事后从正向子集外推总体有效性。

## 8. 决策门槛与停止条件

**第一关：E0 是否能发现真实的目标切换？**

- 若绝大多数病例掩码相同、仅单方关闭或被多规则并集合并抵消，判定为**评测覆盖不足**，明确列出受影响比例；首先设计具有真实负证据目标的**新开发集**，不要在旧数据上扩大偏置强度寻找收益。
- 若有足量非零且掩码不同的病例，进入 E1，报告真实数量，不凭空宣称“样本足够”。

**第二关：参考正确标注条件下 OS 是否优于 OF？**

- 若 OS 没有观察到有意义的 OAR、PairAcc、总体准确率或决策边际方向改善，或存在明显不适用误用／原正确样本损伤，结论为**目前没有支持核心目标切换创新的实证证据**。保留负结果，暂不优化模块一、跨模型或正式验证。
- 若 OS 在明确发生目标切换的病例中出现可解释的净正向效果，且没有相应的安全性退化，视为**值得继续探索的机制信号**，但不是已经证实论文主张；进入 E2，并用新指南的独立测试确认。

**第三关：预测标注版本为什么没有重现 Oracle 效果？**

- 若 OS 优于 OF、而 B3 不优于 B2：优先处理模型自标注的相关性／适用性／证据错误，冻结一次最小修正后到**新指南开发集**验证，不能在旧 40 对反复改到正向为止。
- 若 OS 与 OF 都无优势：考虑调整或停止“按适用性切换注意力目标”的主方法，不再继续叠加模块。
- 如果报告的证据只来自掩码改变、单头导数或 logits 边际，而没有行为层面改善，必须将其称为**机制线索**，不可据此直接宣称方法有效。

**独立验证暂不启动**；只有冻结方案后、开发阶段存在可重复的核心净收益且 OAR/保持率无不可接受损伤，才准备按指南隔离的 **60–80 对新反事实病例**，并事先确定主要结局和最小有意义效应。不得通过同一开发集的非显著结果认定两方法等效。

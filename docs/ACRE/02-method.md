# 02 · ACRE 收敛方法定义

> 研究题目：*When Should a Rule Apply? Applicability-Conditioned Attention Steering for Guideline-Grounded Clinical Decisions*  
> 方法名称：**ACRE — Applicability-Conditioned Relational Attention Editing**  
> 状态：待实验验证的设计规范；相关评审见 [01](01-design-review.md)。

## 1. 任务与问题定义

输入为临床指南 $G$、患者记录 $P$ 和问题 $Q$。将指南中的第 $i$ 条规则记为

$$
r_i: C_i(P)\Rightarrow A_i,
$$

其中 $C_i$ 为适用条件，$A_i$ 为推荐动作；例外条款可记为 $X_i$。

- **闭卷决策** $d_0$：模型不读取指南时做出的决策。
- **指南决策** $d_G$：按当前患者条件及指南推导出的决策。
- **有效冲突**：

$$
C_{\mathrm{eff}}=\mathbb{I}[d_G\neq d_0].
$$

有效冲突依赖于患者与当前模型，而不是仅由指南文本和模型参数的表面不一致决定。

### 1.1 四类评估样本

| 类别 | 判定依据 | 期望行为 |
| --- | --- | --- |
| 适用 + 冲突 | 规则适用，且 $d_G\neq d_0$ | 执行当前患者适用的指南建议 |
| 不适用 + 表面冲突 | 规则的候选动作与模型先验表面冲突，但当前患者不满足规则条件 | 不套用不适用规则 |
| 无冲突 | $d_G=d_0$ | 不因注意力干预引入损害 |
| 信息不足 | 关键条件缺失或无法判断 | 仅在数据标注允许时，给出信息不足的结论 |

**标注注意**：不适用规则的候选推荐动作 $\hat d_{G,i}$ 不等同于综合所有适用规则后的 $d_G$。样本分层须明确采用何种规则候选、适用性真值和闭卷模型输出，避免出现类别定义上的逻辑循环。

所有主要实验结果需按以上类别分层。

## 2. 模块一：规则与患者关系抽取

该模块复用现有检索、推理与符号校验工具，不将关系抽取本身声称为 ACRE 的新算法。

### 2.1 规则解析

用语言模型将指南规则解析为**条件—动作—例外**三部分，并保留原文 span 与 token 索引。在 MedCalc 类型的任务上直接读取可执行规则或计算器定义，减少抽取误差。

### 2.2 问题相关性

使用 MedCPT 估计问题 $Q$ 与规则 $r_i$ 的相关性 $\rho_i$。正式实现需固定取值范围、归一化与多规则聚合方式。

### 2.3 条件与证据的关系

对规则条件 $c$ 与患者证据 $e$ 的每个候选配对，以临床自然语言推理（NLI）识别：

- 蕴含：证据支持条件；
- 矛盾：证据否定条件；
- 无法判断：证据不足或关系未知。

数值、时间、否定和计算类条件由规则程序复核。保存关系类别、置信度 $s_{i,c,e}$、条件 span 与证据 span。

**实现约束**：匹配偏置对“支持条件”和“否定条件”的关键关系均可给出非负增强；应区分关系方向与“配对可信度”，避免把 NLI 的矛盾类别误编码成负注意力权重。

### 2.4 软适用性

根据所有必要条件与例外触发情况合成规则适用性概率 $p_i$。原始设计的逻辑是“必要条件都满足且例外未触发”，但具体概率合成和校准方法仍需在实现前固定。

### 2.5 闭卷冲突强度

令 $\hat d_{G,i}$ 为从规则 $i$ 的动作导出的候选决策，定义

$$
c_i=1-P_{\theta}(\hat d_{G,i}\mid P,Q),
$$

其中 $P_{\theta}$ 由模型闭卷预测取得；**禁止使用测试集金标签来计算 $c_i$**。

为每条规则定义门控：

$$
g_i=\rho_i\,c_i.
$$

当所有 $g_i<\tau$ 时，按原始方案不执行注意力编辑。这个门控决定是否存在值得增强的指南相关信号；规则是否适用主要通过后续目标选择体现，而非直接以 $p_i$ 乘断所有干预。

### 2.6 模块输出

每条规则至少输出以下结构：

| 字段 | 解释 |
| --- | --- |
| $\rho_i$ | 规则与问题的相关性 |
| $p_i$ | 规则对当前患者的软适用性 |
| $c_i$、$g_i$ | 闭卷冲突强度、规则门控 |
| $s_{i,c,e}$ | 条件—证据配对关系及可信度 |
| 条件、动作、例外、支持证据、否定证据的 token spans | 供后续注意力偏置使用 |
| 关系类别与未知标记 | 用于区分蕴含、矛盾和信息不足 |

## 3. 模块二：基于反事实效果选择注意力头

### 3.1 两类对照样本

1. **条件对照**：保持指南规则不变，只改变一个影响适用性的患者属性。
2. **动作对照**：保持患者不变，只改变指南规则中的推荐动作。

优先由可执行规则程序产生对照，不依赖额外人工标注。对照必须验证只变更目标因子，避免混入其他临床状态变化。

### 3.2 筛选流程

1. 使用 **attribution patching** 在所有注意力头上粗筛。
2. 对排名前 $K$ 个候选头执行实际 **activation patching**。
3. 按行为改善与副作用对头 $h$ 打分：

$$
U(h)=
\Delta\mathrm{Acc}_{\mathrm{applicable\ conflict}}(h)
-\lambda\,\Delta\mathrm{Misapply}(h)
-\mu\,\mathrm{Damage}_{\mathrm{no\ conflict}}(h).
$$

其中误用项衡量对不适用规则错误套用的变化，无冲突损伤项衡量干预引起的性能退化。三项的量纲、基准差值方向及归一化必须固定后再比较。

- 对条件变化敏感的头组成 $\mathcal H_{\mathrm{match}}$。
- 对动作变化敏感的头组成 $\mathcal H_{\mathrm{dec}}$。
- 两组可重叠；若头重叠率超过约 **70%**，合并为一组，并如实报告该结果。

头集合**只在独立校准集**确定；与测试集在指南或计算器层面严格隔离。

## 4. 模块三：适用性条件化的注意力偏置

**只有一个干预算子**：在选中头的注意力 logit 上加偏置。

$$
\widetilde S^{(\ell,h)}_{tj}
=\frac{q_t^{\top}k_j}{\sqrt{d_k}}
+\gamma B^{(\ell,h)}_{tj}.
$$

其中 $t$ 为 query token 位置，$j$ 为 key token 位置，$\gamma$ 为在开发集选定的偏置强度。

### 4.1 匹配头：条件—证据配对

对 $h\in\mathcal H_{\mathrm{match}}$，query 取患者证据 token，key 取与该证据对应的规则条件 token。

原始设计中的简写为：

$$
B_{tj}^{\mathrm{match}}=\sum_i g_i\,s_{ij}.
$$

**实现时应将此式展开为带 token 对掩码的形式**，避免把证据索引和 key token 索引混为一谈。可以等价地写成概念性定义：

$$
B_{tj}^{\mathrm{match}}
=\sum_{i,c,e}g_i\,s_{i,c,e}\,
\mathbb I\big[t\in\operatorname{span}(e),\
j\in\operatorname{span}(c),\
(c,e)\text{ 已配对}\big].
$$

未命中的 token 对偏置为零。蕴含与矛盾证据都可以被强调，因为二者均可能影响规则是否适用。

这里才存在**真正依赖 query–key 配对关系的干预**。

### 4.2 决策头：按适用性切换目标

对 $h\in\mathcal H_{\mathrm{dec}}$，在生成位置施加与 query 位置无关的 key 端偏置：

$$
B^{\mathrm{dec}}_{\cdot j}
=\sum_i g_i
\left[
p_i\,\mathbb I(j\in A_i\cup E_i^+)
+(1-p_i)\,\mathbb I(j\in E_i^-\cup X_i)
\right]\kappa_i,
$$

其中：

- $E_i^+$：支持规则条件成立的患者证据；
- $E_i^-$：否定规则条件的患者证据；
- $X_i$：规则例外条款；
- $\kappa_i$：适用性置信度，例如 $\lvert2p_i-1\rvert$。

由此，当规则**适用**时侧重动作与支持证据；当规则**不适用**时侧重否定证据与例外。当适用性不确定且经校准的 $p_i$ 接近 0.5 时，$\kappa_i$ 降低偏置。

**新颖性边界**：在固定的生成查询位置上，$B^{\mathrm{dec}}_{\cdot j}$ 形式上是 key-only 的 token 偏置，而非新的 token 对算子；此处可验证的创新点在于**随适用性选择关注目标**。

### 4.3 约束与实现选择

- **不默认使用负偏置**；压低不适用规则动作只做独立消融。
- 输入顺序固定为 **指南 → 患者 → 问题**，确保因果掩码下患者证据可以关注其前面的规则条件。
- 使用 PyTorch **FlexAttention** 的 `score_mod` 实现偏置。与 SEKA 的效率差异需独立测量。
- $\gamma,\lambda,\mu,K$ 只在开发集确定，主实验各数据集共用一组；逐数据集调参只在附录报告。
- 若同一头位于两组，需按 query 位置构造兼容的匹配与决策偏置，避免重叠掩码时重复计算。
- 实现需检查 token span 对齐、因果掩码、分词差异及增量解码时的 KV 缓存行为。

## 5. 推理伪代码

~~~text
输入：指南 G、患者 P、问题 Q、语言模型 θ
      离线选出的 H_match 与 H_dec

1. 解析规则与患者关系：
   得到每条规则的 ρ_i、p_i、c_i、s_{i,c,e} 和各类 token spans。
2. 对每条规则计算 g_i = ρ_i * c_i。
3. 如果所有 g_i < τ，则跳过干预并直接解码。
4. 否则，基于条件—证据配对构造 B_match；
   基于适用性及候选动作/证据/例外构造 B_dec。
5. 在指定层与注意力头注册 score_mod：
   attention_score += γ * B。
6. 解码并输出决策 y 和推理过程。
~~~

推理额外开销包括一次闭卷前向、NLI／符号规则调用及偏置计算；需报告端到端延迟与显存，而非只报告注意力核函数本身的耗时。

## 6. 论文主张与验证

**方法贡献 1：适用性条件化的注意力引导。** 规则是否适用决定强调动作和支持证据，还是强调否定证据和例外；匹配头进一步使用条件—证据配对偏置。

**方法贡献 2：反事实效果导向的选头。** 将规则正确执行、错误套用及无冲突损伤纳入共同的选择目标。

**待验证的实证发现（非预先宣称的贡献）**：通用注意力增强可能使“不适用 + 表面冲突”样本中的规则误用增加；只有 RQ1 预实验支持时才纳入正文叙事。

## 7. 预先锁定的实现未决项

1. 多条指南规则相互冲突时，如何生成候选决策、综合 $d_G$ 并判定覆盖关系。
2. 必要条件与例外的概率聚合、$p_i$ 的校准方式和“未知”的判定。
3. $\rho_i$、$s_{i,c,e}$、$c_i$ 的归一化，以及多规则叠加导致偏置强度扩张时的处理。
4. 反事实选头分数的量纲、patching 基准和实际激活修补协议。
5. FlexAttention 在各目标模型与解码实现上的兼容性，以及是否保持原模型输出可复现。

这些是实验前需要冻结的协议，不应在测试结果已知后调整。

# 03 · ACRE 实验设计与评估协议

> 状态：实验计划，**不含已完成实验结果**。各数据集规模与方法出处由原始评审提供，均需核验，见 [参考文献核验清单](05-reference-checklist.md)。方法定义见 [02](02-method.md)。

## 1. 研究问题

| 编号 | 研究问题 | 对应实验 |
| --- | --- | --- |
| **RQ1** | 现有注意力引导方法是否会将规则错误套用到不适用的患者？ | 预实验：InstABoost、SEKA、AutoPASTA 的不适用规则误用率 |
| **RQ2** | ACRE 能否提高适用冲突准确率、降低误用率，并维持无冲突性能？ | 四类样本分层的主结果表 |
| **RQ3** | 增益主要来自目标选择、条件—证据配对还是反事实选头？ | 对应组件的独立消融 |
| **RQ4** | 增益是否只是将外部模块已得出的答案重新注入模型？ | 外部流水线直接作答、结构化提示、不提供适用性的变体、关系噪声注入 |
| **RQ5** | 方法能否跨数据集、跨模型迁移，是否在高风险反事实输入下安全？ | 外部基准、迁移实验、安全压力测试 |

**首先执行 RQ1 和 RQ4**：两者决定论文是否具备独立的方法贡献及其叙事基础。

### 2.1 标注与数据隔离原则

1. **两类金标准分开汇报**：
   - **程序可验证金标准**：用于严格决策正确率、反事实因果对照与选头分析。
   - **原始参考答案**：用于数据集整体效果；不得与程序可验证样本混合为一个不加区分的准确率。
2. **校准集、开发集、测试集的用途分离**：头集合只在校准集确定；超参数在开发集选；测试集只用于一次性评估。
3. **按指南或计算器划分**校准与测试，而不仅按单个题目随机拆分。成对反事实样本必须整体位于同一分区。
4. **四类分层**：适用 + 冲突、不适用 + 表面冲突、无冲突、信息不足；缺少足够信息或明确参考标签时，不强行计入相应类别。
5. **外部工具输入审计**：不得向 NLI／规则模块提供测试答案；记录解析错误、未匹配条件与例外规则，避免样本筛选引入偏差。

### 2.2 数据使用前置工作

需要对每个数据集核验：公开下载地址、版本、题目许可、任务形式（多选或生成）、指南版本、可用的患者证据跨度、反事实配对信息、是否具备规则适用性标签，以及可否生成条件／动作对照。

## 3. 实验模型

### 3.1 开放权重主模型

需要获得注意力分数与头级激活的访问权限。原始方案建议至少覆盖三个模型家族和两种规模，例如：

- Llama-3.1：8B、70B；
- Qwen 系列：7B、32B 对应规模的可用模型；
- 一个开放权重的医疗领域专用模型。

具体 checkpoint、上下文窗口、推理精度、attention kernel 和硬件配置须在实验前冻结。上述型号仅为候选，不表示均已完成兼容性验证。

### 3.2 闭源对照

闭源模型仅运行**提示类基线**，用作外部参考；不得与可访问权重模型上的注意力编辑进行不公平的实现级比较。相关限制写入论文局限性。

## 4. 比较方法

| 类别 | 基线 | 必须控制的变量 |
| --- | --- | --- |
| 提示类 | 标准提示；分步执行／思维链提示（CoT） | 指南、患者、问题、解码设定 |
| **强提示基线** | **把模块一的结构化关系直接写进提示** | 提供与 ACRE 相同的 \(p_i\)、条件—证据及例外信息 |
| 注意力引导 | PASTA、AutoPASTA、InstABoost、SEKA／AdaSEKA | 同一模型、同一评测样本、可比的片段选择和调参预算 |
| 知识冲突 | JuICE、ProbeRAG | 在各方法有效的原始设定下比较，记录适配 |
| **直接作答参照** | **外部关系／规则流水线直接输出决策** | 评估外部模块在不经过生成模型时的性能 |
| **Oracle 分析** | ACRE 使用金标准关系 | 与预测关系的主实验严格分开，不能作为部署性能 |

**公平性补充**：注意力方法应同时报告其**原始论文实现／高亮协议**（可复现时）和**统一使用模块一片段的控制版本**。后者用于隔离“目标定位质量”，不能以改动后的版本取代原方法而不加说明。

“外部流水线直接作答”是判断信息是否已被上游模块充分利用的关键参照，不能仅因其位置在流水线前端就称作数学上的准确率上限。金标准关系版本则属于 oracle 分析。

## 5. 主要与辅助指标

### 5.1 主要指标

| 缩写 | 指标 | 统计口径 | 方向 |
| --- | --- | --- | --- |
| **ACF** | 适用冲突准确率 | 适用且有有效冲突的样本中最终决策正确的比例 | 越高越好 |
| **OAR** | 不适用规则误用率 | 不适用 + 表面冲突样本中，错误执行该规则候选动作的比例 | 越低越好 |
| **NCA** | 无冲突准确率 | 无冲突样本中最终决策正确的比例 | 越高越好 |
| **PairAcc** | 成对准确率 | 一对反事实问题中两个成员均答对的比例 | 越高越好 |

应在报告中固定样本数量、明确错误套用的判定器、区分总体准确率与上述分层指标。对于无法可靠判定规则适用性的样本，单独报告覆盖率或无法评估原因。

### 5.2 辅助指标

- **MEGA-CDP 决策路径一致性**：尽量使用原基准的判定框架，并核对其可复现性。
- **推理与答案一致性**：衡量文本推理是否支持最终决策，避免仅看答案指标。
- **端到端成本**：NLI 与规则处理、闭卷前向、注意力干预、生成延迟；峰值显存。
- **通用能力保持**：如 MMLU 的医学相关子集，排查干预对非目标任务的损伤。
- **信息不足场景**：有可靠标注时统计合理拒答或指出缺失信息的能力。

### 5.3 统计检验

- 二元配对预测的差异使用 **McNemar 检验**。
- 所有主要指标用 **bootstrap 95% 置信区间**；对同一患者、指南或反事实配对的相关性采用适当的成组重采样。
- 多重比较使用 **Holm 校正**。
- 汇报绝对差值、置信区间、样本量及校正后显著性，不仅汇报相对提升。
- 模型版本、随机种子、解码设置和失败样本处理方式需完整记录。

## 6. 消融设计

每项消融只回答一个明确的论点，并保持其他设置不变。

| 消融设置 | 核心问题 |
| --- | --- |
| 整条规则统一高亮 vs 按适用性选择目标 | 目标选择是否有效 |
| 仅 key 端 token 偏置 vs 匹配头的 token 对偏置 | 条件—证据配对是否有独立增益 |
| 无门控 vs 只用冲突门控 vs 冲突与适用性条件化 | 门控机制是否必要，哪部分带来收益 |
| 全部头 vs 通用上下文头（JuICE 类）vs 反事实选头 | 反事实选头是否优于通用选择 |
| 硬适用性 \(a_i\) vs 软概率 \(p_i\) | 概率表示是否改善鲁棒性 |
| 仅匹配偏置、**不提供 \(p_i\)** | 方法是否超出外部适用性答案注入 |
| 加入负偏置 vs 默认非负偏置 | 压制不适用动作是否必要 |
| 关系噪声 0%、10%、20%、30%、40% | 上游判定出错时的性能退化 |
| 头集合从 MedCalc 迁移到 MEGA-CDP | 选头是否跨任务泛化 |

**关于门控消融**：原始方案的 \(g_i=\rho_i c_i\) 不直接包含 \(p_i\)。因此“冲突 + 适用性”应在实验协议中明确指 **适用性条件化目标选择／置信衰减**，不要把没有定义的 \(p_i\) 门控写成已经实现的机制。

### 6.1 噪声注入细则

在**模块一的预测输出**注入指定比例的关系错误，而非修改测试真值。分别检查条件极性、例外触发与 \(p_i\) 的错误；报告每种错误对 ACF、OAR、NCA、PairAcc 的影响。若无法精确控制错误比例，应给出实际观测错误率与注入规则。

### 6.2 必须额外报告的对照

- **无上游软适用性的匹配偏置版本**：切断外部直接给答案的路径。
- **结构化提示与直接作答**：检验模块外信息是否已足够。
- **Oracle 关系版本**：估计上游关系错误导致的损失；不能与预测关系的主结果混为一谈。

## 9. 阶段性决策标准

- 若 **RQ1 不成立**（通用方法未明显增加规则误用），改以“同时提高适用冲突准确率与成对准确率”为主叙事。
- 若 **结构化提示与 ACRE 的差异落在不确定范围内**，优先检验长上下文、多轮场景、关系噪声与推理—答案一致性；仍无独立优势则重审论文定位。
- 若 **匹配头配对偏置没有显著独立增益**，不将其作为论文主要创新。
- 若 **两类头高度重叠**，合并头组并据实解释。
- 若 **噪声下性能急剧退化**，不得声称具有稳健的上游错误容忍性。

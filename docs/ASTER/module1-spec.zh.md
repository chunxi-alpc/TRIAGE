# 模块一确定版：处置盲分支分类器

**确定日期：2026-10-27。主版本：M1-self。输出版本：`aster.action_blind.v1`。**

[主线索引](README.md) · [论文方法](manuscript.zh.md) · [参考实现](../../src/aster/README.md) · [实验计划](experiment-plan.zh.md)

## 1. 唯一默认任务

输入患者文本和仅包含条件的互斥分支组，使用部署时的同一骨干模型，输出组内规则及 `NONE` 的概率分布。模型不抽取患者变量，不调用外部事实核查或自然语言推断模型，不生成处置。证据句不属于首版必需输出。

主方法固定为：**结构化条件视图 + 同一骨干 + 受限分支评分 + 单温度校准 + 概率／间隔弃权**。模块一输出决定模块三的目标和开关；模块二只接受独立金标最小对。

## 2. 输入契约与处置盲边界

```json
{
  "patient": "患者在缓解后约4个月复发，既往未使用H。",
  "question": "根据指南，应选择方案X还是方案Y？",
  "options": {"A": "方案X", "B": "方案Y"},
  "guideline": {
    "groups": [{
      "group_id": "G1",
      "mutually_exclusive": true,
      "ancestor_conditions": ["患者已复发。"],
      "rules": [
        {"rule_id": "R1", "condition": "复发距缓解少于6个月，且既往未使用H。", "action": "方案X"},
        {"rule_id": "R2", "condition": "复发距缓解至少6个月。", "action": "方案Y"}
      ]
    }]
  }
}
```

参考实现只将 `patient`、`ancestor_conditions`、各条 `condition` 和固定任务指令写入提示。`action`、原始 `question`、`options`、标题、说明等字段不读取。原始组编号与规则编号保留在接口外部，模型看到中性代理标签；这样也避免语义性编号泄露处置。每组目前支持 1–25 条规则，再加入 `NONE`。

若原问题包含判定所必需的非处置语境，调用者可以单独提供 `task_context`，并声明 `task_context_verified=true`。该字段必须只含核验过的条件语境。原问题含有处置名称时，不能直接把它复制到该字段。

**必须保留历史事实。** “既往未用 H”“某治疗后复发”“检查结果为阳性”是患者事实或条件。不能按药名、治疗名全局删除。输入适配器也应将病例中的待选择处置建议与已发生的病史区分；参考实现不声称能自动识别任意患者文本中的建议泄漏。

**互斥性由数据提供者核验。** `mutually_exclusive=true` 是外部核验声明，不是程序完成了语义证明。程序拒绝缺少声明、空组、超过标签池的组、重复规则编号及完全重复条件；自然语言等价、部分重叠和切分错误仍须离线质控。并行建议不使用这一单选接口。下游组必须保留完整祖先条件。

固定患者、条件及条件语境，只改处置、原问题中的处置提示或选项时，构造的 M1 提示必须逐字一致。相同确定性前向因此接收相同 token IDs。它保证该输入通道不传入被排除字段，不保证骨干内部没有医学先验，也不保证条件字段已无推荐结论。

## 3. 标签评分与概率

例如输入规则 `R1/R2/NONE` 映为 `A/B/C`。每个标签在**实际聊天模板和答案边界**上必须对应恰好一个新增、互异、非特殊词元。不能将 `R1` 的首词元当作整条规则的分数。模板与思考设置变化后必须重新验证。

参考实现一次前向读取该组全部合法标签的下一词元 logits，不调用自由生成。使用

$$p_T(r\mid g)=\frac{\exp(z_r/T)}{\sum_{u\in g\cup\{\mathrm{NONE}\}}\exp(z_u/T)},\qquad T>0.$$

该分布是合法标签集合内的条件分类概率。它不等于自由文本生成频率。模型填写的 JSON 小数、采样次数或遗漏候选的 top-k 返回值不能替代完整分数。没有合格单词元标签、上下文超限、非有限分数或分数长度错误时，参考接口报错；调用者记录失败并停用干预，不得用截断、零填充或伪造 `NONE` 掩盖错误。

首版仅支持直接标签分类。`HFLabelScorer` 默认传入 `enable_thinking=false`，模型应处于 `eval()` 且未安装模块三干预。若某个模型的模板不支持直接分类，需另做适配和验证，不能把思考起始词元当答案标签位置。首词元分类和自由回答的差异可参见 [Wang 等，2024](https://aclanthology.org/2024.findings-acl.441/)。

## 4. 单一温度与弃权

每个骨干及固定提示协议，在开发／校准资料上拟合一个全局正温度：

$$T^*=\arg\min_{T>0}-\sum_i\log p_T(y_i\mid x_i).$$

不按原子、规则组或病例分别拟合。测试集固定温度。温度缩放采用 [Guo 等，2017](https://proceedings.mlr.press/v70/guo17a.html) 的后处理方法；它不改变类别排序，不能纠正已经选错的分支。模板、标签顺序或模型变化时，不应直接沿用旧温度。

$$\hat r_g=\arg\max_r p_T(r\mid g),\quad m_g=p_{(1)}-p_{(2)},\quad H_g=-\sum_r p_T(r\mid g)\log p_T(r\mid g).$$

$$a_g=\mathbf1[p_{(1)}<\tau_p\ \lor\ m_g<\tau_m\ \lor\ \text{最高概率并列}].$$

阈值取值范围均为 $[0,1]$，开发集确定后冻结。最大概率、间隔、熵都只是置信度摘要。主规则使用前两项；熵供评价，不作为额外默认门槛。熵单位为纳特，不同组大小的比较另报归一化熵。

`NONE` 统一定义为：**根据当前提供的信息，无法确认任何候选分支适用，包括无匹配或关键信息不足。** 它是一个语义类。`abstain` 是分类置信度策略。

| 分布／状态 | `prediction` | `abstain` | 模块三行为 |
|---|---|---|---|
| R1 最高且通过开发阈值 | R1 | false | R1 正增益，其他实际规则负增益 |
| R1=0.46、R2=0.42、NONE=0.12，未通过阈值 | R1 | true | 本组全零 |
| NONE 最高且高置信 | NONE | false | 本组全零 |
| 最高概率并列 | 按输入顺序保存最高标签 | true | 本组全零 |
| 祖先路径未确认 | 保留本组原始结果 | 保留原始弃权状态 | 以 `eligible=false` 关闭本组 |

不得在弃权时把 `prediction` 改成 `NONE`。未记录也不自动满足否定条件。无有效分类输出属于接口失败，应独立记录，不冒充语义 `NONE`。

## 5. 输出字段

顶层包括 `schema_version`、`groups` 与 `metadata`。每组输出：

| 字段 | 含义 |
|---|---|
| `group_id` | 原始组编号 |
| `probabilities` | 全部规则与 NONE 的归一化概率 |
| `prediction` | 原始概率最高类别，即使弃权也保留 |
| `probability` | 最大概率 |
| `margin` | 最高与次高概率差 |
| `entropy` | 自然对数熵 |
| `abstain` | 置信度判据的拒绝决定 |
| `intervention_allowed` | 未弃权且预测非 NONE；最终仍受可达性约束 |
| `prompt_sha256` | 条件提示文本摘要；不代表完整模型或模板指纹 |
| `logits` | 仅 `include_logits=true` 时输出，供开发校准及审计 |

顶层元数据记录提示版本、温度、阈值、熵单位和是否使用独立条件语境。完整模型身份、聊天模板、分词器、真实 token IDs、数据划分清单仍需实验运行器保存；当前文本哈希不能替代这些记录。

## 6. 如何进入模块三

只对可可靠到达的组启用以下规则：

$$g_r=\begin{cases}
0,&a_g=1\ \lor\ \hat r_g=\mathrm{NONE}\ \lor\ e_g=0,\\
+g^+,&r=\hat r_g,\\
-g^-,&r\ne\hat r_g.
\end{cases}$$

首版的 $g^+,g^-$ 是开发阶段固定值。连续间隔增益、集合内不压低、整棵子树抑制都属于后续消融。`rule_gains` 只实现上述映射；它不遍历树、不推断后代可达性，也不修改注意力。模块二方向通过独立金标数据估计，不接收这里的概率来训练。

某组零增益只表示该组不编辑。只有所有组全零，且执行输入、模型设置与缓存均与原模型一致时，才能称整例回退。实际缓存、位置旋转与键编辑仍须模块三实现后验证。

## 7. 评价与版本状态

主方法为 M1-self；M1-NLI 仅作为可选辅助消融；M1-oracle 以规则金标作为诊断上界。医学自然语言推断任务与分支多分类并不等价，这不构成骨干模型在所有数值或否定案例上更优的证据。

必要指标为全体分支准确率、NONE 子集表现、NLL、Brier 分数、ECE、接受覆盖率、接受组错误率和非零干预覆盖率。按数值、时间、否定、缺失信息等切片评价，不需要恢复在线原子抽取。完整系统还须与同 M1 输出的直接映射、附注、裁剪和融合比较。

本版不提供保形覆盖或 LTT 风险保证，不引入多模型融合、复杂证据绑定、原子概率乘积或多个外部专家。参考实现的契约测试不等于模型准确率与校准已被验证。当前完成范围见[实现状态](implementation-status.zh.md)。

# 2026-10-27 主线修订：为何采用处置盲分支分类

[主线索引](README.md) · [模块一确定版](module1-spec.zh.md) · [论文工作稿](manuscript.zh.md)

**术语更新（2026-10-28）：** 模块一正式命名为处置盲适用性评估（Action-Blind Applicability Assessment, ABAA）；原“条件视图”统一称为“处置盲输入”。受限分支分类是 ABAA 的判定实现。

## 决定

采用用户最新模块一作为唯一默认版本。ASTER 改为三个职责明确的模块：在线分支分类、离线适用性方向学习、在线规则键平移。旧两阶段掩码与证据员方案不再定义主方法。

## 两个比较对象

仓库改版前的 `main` 采用同一上下文内的盲判掩码、证据员、软否决与执行阶段对数门控。本次附件提出了三模块和有符号平移，但仍保留原子抽取、类型核查、概率融合、保形集合及 LTT。用户最新消息进一步简化模块一。本次选择“附件的职责分离与离线方向思路 + 最新模块一”，并收窄附件中未经证明的保证。

| 问题 | 改版前／中间方案 | 本版决定 | 理由及代价 |
|---|---|---|---|
| 模块一任务 | 条件原子化、证据定位、核查、融合 | 直接互斥分支多分类 | 对齐最终判定目标，减少接口；数值和否定仍可能出错 |
| 判定模型 | 证据员或医学推断辅助 | 复用部署骨干 | 减少额外依赖；不预设比专用模型准确 |
| 处置盲 | 跨层掩码或文本替换 | 结构化处置盲输入，单独前向 | 输入不变性易核验；原始文本切分仍需质控 |
| 不确定性 | 保形集合、风险认证 | 单温度、概率和间隔弃权 | 易实现、易做覆盖率分析；失去原认证结论 |
| 模块二监督 | 易混入 M1 标签或共享编译器 | 独立金标最小对 | 分离“判错”与“方向失效”；仍需离线数据构造 |
| 在线执行 | 证据绑定、软否决、窗口强调 | 规则编号与处置段的有符号键平移 | 算子职责清楚；查询方向、缓存及顺序须实测 |
| 论文贡献 | 多组件联合增益难归因 | M1 与执行器同信息比较 | 必须正面对比直接映射及文本执行器 |

## 必须同时修正的定义

1. **预测与弃权分开。** 低置信 R1 仍保存 R1；不能改成 NONE。
2. **标签分词必须验证。** 使用单词元中性代理标签；不能默认 R1 是单词元。
3. **处置盲保留病史。** 不删除“既往未用 H”等决定条件的事实；也不将条件标题中的推荐结论带入提示。
4. **互斥与祖先是前提。** 并行建议不能强制单选；上游不确定时下游不激活。
5. **回退有范围。** 一组全零只关闭该组；整例全零并保持原计算才是原模型回退。
6. **校准不是纠错或认证。** 正温度不改 argmax，阈值不提供有限样本伤害保证。
7. **键方向不保证所有查询同向。** 必须在真实部署顺序上测可读性；固定查询的局部公式不推出准确率单调。
8. **不把离线方法写成普遍优于训练。** 适配器也能关闭；优势须在同数据、同预算及指南更新设置中验证。

## 论文应重点回答的问题

M1-self 是否在处置交换下保持输入不变，且在分支判断上足够可靠？可靠性在哪些条件类型失效？M2 是否存在能迁移到真实提示顺序的方向？M3 相比使用同一 M1 信息的直接映射、文本附注与裁剪，是否改善了生成路径？拒绝低置信组后，错误干预下降了多少，同时损失多少覆盖？

这些问题比“额外模型是否完成了主要推理”更容易归因，但不保证实验更好。若 M1-only 已足够，选择题无需用更复杂执行器取得相同答案；注意力贡献应由路径生成和匹配成本实验支持。

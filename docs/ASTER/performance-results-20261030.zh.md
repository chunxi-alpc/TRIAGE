已在物理 GPU 0、1、5、6 续跑原 official_test 清单，执行代码 `901075e6e6b33bf6ed7a75eb0d83d2cef0fa65b6`。模型修订、方向、秩、头集、温度、接受阈值、增益、种子、输出预算、采样及评审重复次数均未改变。原冻结文件未改写，原病例/方法成功、技术失败和评分失败全部保留，只补缺失单元。

## 实测瓶颈

对180例已有记录统计，评分按真实未复用调用计时，剔除相同表示复用的重复计时：

| 阶段 | 已计时耗时比例 |
|---|---:|
| Qwen 官方评分 | 69.3% |
| 13种方法生成合计 | 29.4% |
| 处置盲分类 | 1.3% |

原始长指南 native 生成单独占总计时16.4%，其他12种方法合计约13.0%。未复用评分677组，平均46.73秒，P90约91.81秒，最长251.21秒；已有1644份相同表示评分复用。缓存评分不能重复计入实际GPU工作量。

**说明纠正：**固定官方评分源码对路径与结论各进行5次独立模型调用，每个未复用答案共10次generate。先前文档“一次请求中五个结果”的表述错误。实际运行代码一直执行上述次数，优化没有减少次数。

## 已部署的优化

1. 同一评分上下文的相同完整提示复用首个完整前向结果，每次返回独立的DynamicCache副本和首logits。保留HF原generate、原采样及RNG调用顺序。每组10次评分调用只需2次真实提示预填充，另8次回放缓存。
2. 单词元解码使用CUDA Graph重放原Q/K/V投影、Q/K归一化、RoPE，以及原层尾归一化、MLP和残差加法。动态缓存更新、全注意力、算术顺序、精度和采样保持原样。没有编译融合或量化。图输出逐次克隆，防止后续覆盖。
3. 注意力观测使用已知的CPU绝对位置，避免每词元每选中层GPU标量同步。仍在原6个位置按原顺序求和，结束时统一搬回已计算的小张量。
4. 对照中原始长指南 native 的CUDA Graph路径实测变慢，正式仍使用其原有经过验收的执行路径。额外保留完整指南缓存的尝试也未带来可靠收益，已恢复原单槽缓存策略。这两项没有部署。

## 真实权重验收与收益

使用既定开发来源的首个原始病例，未依据官方测试成绩选择样本。

- 2个来源、13种方法，共26单元：完整输出词元、文本、注意力记录、编辑统计均与参考一致；首logits误差0。
- 另对3个固定后续词元比较，全部36层K/V及logits最大误差均为0。
- 两组完整评分，每组实际10次模型调用：所有评分生成、最终CPU RNG及CUDA RNG状态均一致。
- 63项既有回归全部通过，无跳过。额外CPU真实微型Qwen测试覆盖缓存命中、掩码变更及forward恢复。
- 评分耗时分别从15.30→12.16秒、34.59→28.52秒；合计49.89→40.68秒，**减少18.45%，吞吐约1.23倍**。
- 验收峰值显存约45.7GB。正式长输入仍可能接近80GB，原始长度与失败保留规则不变。

完整图候选中包含额外保留完整前缀及native图重放，开发集生成总耗时130.45→144.54秒，出现回退；因此不能把它称为全阶段加速。额外比较恢复原前缀策略后native仍为47.05→51.76秒，最终对native完全恢复原执行函数。正式采用评分加速、结构生成图重放、观测同步优化，保留原native和原前缀策略。

按既有耗时占比推算，预计整体节省约10–15%，尚不是完整新队列的实测收益。剩余约3–4.5天是估计，取决于后续指南长度、答案差异及评分生成长度；不能由两个开发病例承诺固定完成时间。

## 实现与统计审阅

评分缓存的完整键包含模型配置/权重/源码与参考指纹、案例、指标、完整请求和重复序号；方法名排除。每次方法/案例/指标切换重置序号，五次评分分别采样，没有把一次评分重复当作五次。本轮报告为 260 次实际请求、770 次缓存命中、零失败请求；未发现可以解释明显错分的缓存复用缺陷。零强度和无钩子的完整答案及评分一致。

缓存只消除相同请求的重复采样差异。不同答案仍由同一生成模型充当评分器，以不同的请求派生随机种子评分；这不是独立模型，也没有完整估计评分器不确定性。现有区间仅重采样保存的案例分数，固定了评分抽样结果。分组 bootstrap 实现保留整组并按案例加权，未发现当前 16 个一例分组上的明显计算错误。

现有报告只保存相对零强度的区间；与文本强调/两种融合的直接配对区间尚未报告。应在服务器用现有 `compare_methods` 分别以这三者为 reference 补算，不需新 GPU。不同方法差值区间不能用已有区间端点相减替代。

# 开发阶段规则抽取修复

首轮16份冻结train_val指南共487个抽取条目，仅60条通过旧检查。独立CPU诊断发现：188条的条件、动作和例外本身逐字存在于原文，但模型重复生成的rule_quote不正确；50条条件与动作完全相同，另78条条件包含完整动作；99条至少一项锚点不是仅空白差异。全部原输出保留，未读取临床评分挑选修复。

新增程序只用逐字存在的条件、动作、例外，在原指南中恢复包含全部锚点的最短连续段落，同长取最早位置，保留中间全部文字和限定条件。不改写原文、不猜缺失锚点、不接受条件包含完整动作、不补截断尾项。6项服务器合成测试通过。

对原16份抽取做CPU重放后，有规则病例由6增至12，没有新增模型前向，也没有重新生成临床答案。这不是语义正确率或准确率改善。有的恢复段落长达19319字符，说明锚点可能相距很远；该事实保留，不能据来源匹配宣称临床关系正确。详见source_span_replay_audit.json。

第二版开发提示明确区分患者条件与建议动作，提供不含真实测试内容的中英文合成格式例子，跳过标题/定义/引用，不让模型重复编写完整段落，而由原文锚点恢复。16份原开发指南、seed0、4096生成预算、65536上下文和Qwen检查点均不变。新增抽取验证已排在GPU1当前注意力任务之后，预计35–65GiB、1–3小时；不改变已经运行的首轮方法/对照。

这属于第2版开发候选，尚未接入正式临床比较，更未冻结为外部评测方法。原43组仍完整评分，保留所有负结果。后续须检查第二版实际抽取、在开发集完成同信息对照后才可冻结；不能把本次CPU重放冒充新临床效果。

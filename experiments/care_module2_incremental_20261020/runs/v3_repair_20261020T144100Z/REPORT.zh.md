# 候选 token / N5 拟合修复后的最终结果

日期：2026-10-20。状态：开发集与获准执行的测试集均已完成，所有进程退出码为 0；N1 测试和 N4 联合实验按原登记门槛停止。没有重训/调用 A1，没有重跑 B1–B4、旧符号实验、旧注意力扫描、旧 8B 来源冲突或 A1 原 24 例对照。

## 结论

原来“全部选零”不能作为方法无效的证据，因为候选评分存在实现错误。修复评分后，N3 的 route 在开发集选择 beta=1，mean 选择 beta=.5；N1/N2/N5 的 route 仍选择 0。完成纠正后的测试后，**低秩 route 仍未证明优于同信息量的简单策略**。N3 mean 有探索性改善，但不优于文本，也不是预登记的低秩 route 主比较。

这些测试病例的旧结果已经被看过。本轮是实现修复后的可追溯重评，不能重新称为未见留出确认，不能据此调整参数再测试。

## 修复与 CPU 验证

- 候选定义为最终 `Answer:` 后的精确接续 ` A`、` B` 等。检查完整 prompt+接续分词的前缀不变、后缀恰为一个 token、解码一致。672 条冻结基础 prompt 全部通过；开发方法提示也在复用和执行时逐个检查。
- 候选并列时选择最小 token ID，与全词表 `torch.argmax` 一致；该规则和候选 token ID 进入新评分缓存版本。旧裸字母 logits 不会被当作新分数。新前向记录候选 logits、概率、差距、并列集及 token ID。
- N5 从原 pair_id、同 family/rule/hash/action/A1 版本的冻结预测构造 T/F 对。得到 23 对、46 个观测，来自 6 个 train 家族，家族配对数为 4/4/3/4/4/4，每对等权。质心和协方差使用完全相同的观测。没有用 gold、参考状态或 A1 正误筛选。
- 训练母集仍为 36 病例/108 个规则信号。46 个进入配对，19 个 U/null，17 个无原始配对，26 个无唯一异号对应项；全部原因保留。评估母集、U/null 和无有效信号病例不删减。
- N5 的“差分均值与目标均值差”偏差范数由 6.3455 降为 0.00000936（浮点求和误差）。训练轴完全复用已有 46 个 GPU 激活，在 CPU 重拟合；N1/N2/N3 训练轴原样复用。
- 22 项 CPU 测试通过：覆盖裸/带空格 token 分歧、边界合并/多 token、真实评分调用、旧缓存隔离、并列恢复、N5 禁止截断、配对身份与版本、打乱顺序不变、不读参考标签、U/null 保留、旧选择不兼容以及 beta=0 的 IIA 不请求 donor 激活。原 oracle/无泄漏检查全部通过。

## 旧输出如何复用

原始完整候选 logits 没有保存，不能补造新候选分数。但当保存的全词表最高概率 token 正好是一个合法候选，且其解码在 tokenizer 词表中唯一时，它必然也是候选集合内的最大值；最小 token ID 的并列规则保证答案也能精确恢复。

据此恢复 798 条开发模型预测，另复用 48 条确定性输出。恢复记录明确标注 `exact_winner_only_from_legacy_global_argmax`，新候选 logits/概率/差距/并列集为 null，旧裸字母分数单独保留。只凭答案即可准确复算本协议按正确率选择的主指标；不能据此分析新候选置信度。非候选全局输出不能恢复，实际补前向；N5 非零旧轴结果不能冒充新轴结果。相同 prompt/spec 共享一次前向，但所有病例分母保留。

没有覆盖旧 v1/v2 结果、旧冻结选择或旧失败日志。原 v2 目录 339 个文件在本轮前后逐个 SHA256 一致。测试复用采取同样规则；48 条闭卷生成直接引用真实旧输出，没有重新生成。

补充答案后结果保留初始问题不决定答案的失败，并未删去错误追问分母。mean 的次指标值得后续研究，但不能用其替代 route 的登记主比较。N5 route/直接 bias 都选择 0，二者相同仅表示当前选择没有干预，不是非零方法等效性证据。

# 开发集强度选择离线诊断

## 结论

“各阶段都选零”直接来自冻结的选参规则：主指标最大、同分选择最小 beta。该规则被离线复算准确重现，未发现选参排序写反。问题在于输入给选参程序的评分，以及部分拟合定义：已确认候选 token 与记录的模型最高概率输出不一致；N2/N3 低秩坐标保留的控制差异很小；N5 协方差拟合使用未匹配、截断的 T/F 列表。

因此，不能把旧“全部选零”的结果解释为所有非零机制均无效。既有数字是原评分程序的结果，保留作为可追溯记录；其中涉及模型能力、非零强度收益及停止门槛的科学解释需重新审视。本次没有重跑任何实验，没有改实验执行代码、数据、拟合张量或冻结选择。

## 1. 原开发集的每种强度

以下均为开发集；N1/N2 另列注册的完整块主指标，N3/N5 为家族平衡准确率（每家族行数相同）。表中依次为 beta=0 / 0.5 / 1。

| 阶段/方法 | 正确数 | 注册主指标 | 原评分下发生的变化 |
|---|---|---|---|
| N1 route | 8 / 8 / 8，分母16 | 0 / 0 / 0 个完整四格，分母4 | 没有预测变化 |
| N1 R-only | 8 / 8 / 8 | 完整四格均0/4 | 没有预测变化 |
| N1 A-only | 8 / 7 / 8 | 完整四格均0/4 | beta=.5 损坏1例 |
| N1 mean | 8 / 8 / 8 | 完整四格均0/4 | 没有预测变化 |
| N1 spectral | 8 / 6 / 8 | 完整四格均0/4 | beta=.5 损坏2例 |
| N1 direct bias | 8 / 7 / 8 | 完整四格均0/4 | beta=.5 损坏1例 |
| N2 route | 4 / 4 / 4，分母8 | 0 / 0 / 0 个双向全对，分母4 | beta=1 纠正1次、损坏1次，同一接收者两种政策一起换答案 |
| N2 mean/direct bias | 均4 / 4 / 4 | 双向均0/4 | 没有预测变化 |
| N3 route | 9 / 9 / 5，分母16 | 56.25% / 56.25% / 31.25% | beta=1 损坏4例 |
| N3 mean | 9 / 9 / 9 | 均56.25% | 没有预测变化 |
| N5 route | 5 / 5 / 5，分母12 | 均41.67% | beta=.5 两例错误答案换成另一个错误答案 |
| N5 direct bias | 5 / 5 / 5 | 均41.67% | 没有预测变化 |

于是原 route 选零的理由分别是 N1/N2/N5 三档同分、N3 零与 .5 同分且 1 更低。N1 的主指标很离散，4个开发家族中任何一个格子失败都会使该家族记零；逐例变化不会自动反映到主指标中。

注意：随机方向、错配与 IIA 对照继承 route 强度，并非各自独立搜索后又发现零最好；文本、过滤、baseline 的 beta=0 仅表示不做数值干预。不能把这些零值当作额外的独立负证据。完整66行网格见 dev_strength_grid.csv。

## 2. 确认的评分实现问题

位置：`src/care_m2_v2/engine.py:30–33,129–132`。程序编码 `A`、`B` 等裸字母作为候选，读取它们的 logits；但所有提示以 `Answer:` 结尾，模型记录的最可能单 token 回答带一个前导空格。

真实 tokenizer：`A` ID=32，` A` ID=362；`B` ID=33，` B` ID=425；`C` ID=34，` C` ID=356。它们不是同一个 token。N1/N2/N3/N5 开发集共56条 baseline 条件记录，最高概率 token 全是合法的带空格选项，原 `unconstrained_is_candidate` 却全部为 false。原 CPU 对齐检查只验证裸字母长度为1，没有验证提示后的实际输出形式，这项检查不充分。

只读取已保存的 `top_unconstrained_token`，去除首尾空白后得到以下离线诊断。不是新增模型推理，不改原选参，也不是恢复完整候选 logits 后的正式重评分：

| route 开发集 | 原计分 beta=0/.5/1 | 已保存最高概率 token 去空白后 beta=0/.5/1 |
|---|---|---|
| N1，分母16 | 8 / 8 / 8 | 11 / 11 / 11；完整四格均2/4 |
| N2，分母8 | 4 / 4 / 4 | 4 / 4 / 4；双向均0/4 |
| N3，分母16 | 9 / 9 / 5 | 9 / 9 / 10 |
| N5，分母12 | 5 / 5 / 5 | 7 / 7 / 4 |

这已足以证明评分选择会掩盖或反转强度效果：N3 beta=1 原来被记为明显下降，已保存的真实最高概率选项却比 beta=0 多对1例。N3 mean 的 .5 和1也从原先9/16变为10/16。但1例改善远不足以证明稳定收益，文本诊断仍为12/16。N2 去空白后的 C/P 控制在每个强度、每个接收者上仍选择相同来源，没有双向切换。

N5 text 的12条中有2条最高概率 token 不是选项，本诊断保留并记为输出不合要求，不删除分母，也不猜测后续生成。其余主 route 网格的最高概率 token 全可映射至合法选项。完整824条逐例记录见 per_case_dev_diagnostics.jsonl。未保存全词表 logits，不能从现有文件恢复所有带空格候选的分数、概率和差距；最高概率 token 的并列情况也不能完整还原。

## 3. 干预真的执行了吗，是否只是强度太小

非零 route 的开发记录均存在实际残差变化；direct bias 的实际 post-RoPE score 修改值为 ±.5/±1。非零 hook 并未被统一跳过。beta=0 与 baseline 共用缓存是预定行为，非零调用有各自的干预规格。选参规则本身准确复现。

beta=1 时，每次 route 编辑的实际残差范数相对于当前位置原残差范数的中位数：N1 1.47%（R/A 各自半强度的单次编辑，不是两次合并净量）、N2 12.03%、N3 10.08%、N5 18.94%。N2/N3/N5 并非都小到数值上完全没有作用；实际范数接近请求值。BF16 有量化误差，特别是 N1 较小改动，但无法解释全部方法的零选择。

beta 含义也不相同：route 是沿选定坐标朝训练目标移动的比例，1为完整坐标替换；mean 是均值差位移系数；direct bias 是 attention score 加数。因此不能直接以同一个数值认为干预预算相同。当前只有0/.5/1，未覆盖所有尺度；但现有证据也不支持先无差别加大强度。N5 的最高概率 token 诊断在1时反而更差。

## 4. 子空间和拟合的具体问题

`engine.py:153–163` 对配对差分先减均值，再用 rank-2 PCA。此定义捕捉差分随内容变化的部分，不保证保留两种控制之间稳定的平均差异。离线读取原 axes.pt 得到：

| 训练轴 | 原均值差长度 | 投影到所选子空间后的长度 | 保留长度比例 |
|---|---:|---:|---:|
| N1 R | 19.654 | 3.350 | 17.05% |
| N1 A | 1.627 | 0.543 | 33.38% |
| N2 C/P | 18.517 | 1.368 | 7.39% |
| N3 D/Q | 40.817 | 3.108 | 7.61% |
| N5 A1 | 16.269 | 16.072 | 98.79% |

N2 同一中性输入上，两个控制目标的投影距离仅1.368；两个控制共同引起的位移长度中位数约14.858。也就是说，较大的残差变化主要是两个控制共享的变化，区分 C/P 的部分较小。这与开发集两个政策始终给出同一答案一致。属于子空间定义与控制目标不充分匹配的证据，不是 hook 没执行，也不能单独证明修改子空间后就会有收益。N3同样损失大部分控制均值差。

N5还有更直接的拟合不一致：train 为26条T、63条F。`fit_axis` 把 T 与 F 的列表按顺序配对，协方差只用前26条F，丢下37条F；目标均值却使用全部63条F。26对里仅1对来自同病例，10对具有同一 rule_id，不能解释为同病例同规则的反事实差分。保存差分的均值与用于控制的两类均值差相差范数6.346。这可能把内容、规则种类或位置差异混入方向。应先修正/明确这个拟合定义，不能将当前结果概括成冻结A1迁移方法本身无效。

## 5. 对三种解释的判断

- 实现问题：确认候选输出形式不匹配；确认N5差分协方差与目标均值使用不同、未匹配的训练样本。原“全部选零”的科学解释不可靠。
- 强度范围：网格有限，N1作用较弱；但N2/N3/N5已发生可观变化，不能把所有结果统一归因于强度太小。优先澄清评分与方向，再讨论是否扩大范围。
- 方法没有收益：原定义的评分程序确实没有选到非零净收益；这不等于方法在正确输出契约下已被否定。离线最高概率 token 对照显示 N3 有小幅改善，N2 仍不双向切换，N5较强干预有损伤，不能给出统一结论。

建议下一步的顺序仅作为分析结论：先固定和验证候选输出形式、明确N5匹配/权重与子空间定义；然后再决定是否另行进行有限的新验证。本次不改变任何冻结选择，不启动新的CPU模型/GPU模型推理，也不重跑旧任务。

# 聊天模板重复起始标记修复

2026-10-27 对 P2 止损继续诊断时，发现 Llama 推理输入重复添加 BOS：聊天模板字符串已以 128000 开头，随后 tokenizer 默认又添加一次，实际输入以两个连续的 128000 开头。Qwen 默认编码不额外添加该标记。

## 证据与影响范围

- 核对旧版 P1/P2 以及重建的闭卷提示共 2907 条/模型。Llama 全部多出一个 BOS；修复后不再重复。Qwen 全部修复前后 token ID 完全一致。
- 直接调用聊天模板的 tokenize=True 路径，与新统一 encode_prompts 函数的编码一致。进一步检查全部提示按实际 batch=4 填充后的有效 token ID，一致性通过。
- P1/P2 逐例计分正确，熟悉标准条件的 338 条输入/模型与 P1 的提示哈希及预测完全一致；不存在统计表将两种条件写反的问题。
- 旧版 Llama 熟悉标准条件下约 97.04% 的回答为编号 2。这是值得诊断的行为，不是重复 BOS 已被证明解释全部退化的证据。修复后结果必须重新运行才知道。

P1 分支生成、P2 分支生成和 P2 闭卷置信度三处统一使用 add_special_tokens=False，避免在已格式化的聊天模板外再加特殊标记。P3 原来已明确关闭额外特殊标记，P4/P5 的分段编码也已关闭。

## 重验与复用

冻结的病例和文字提示保持 v2.1 不变：四卷各 169 例、CS 17 例，仅开发树。新运行在当前目录中，从 P1 开始按同一门槛验收。旧版 P2 的 STOP 及所有原始结果保留，但其 Llama 行使用了有缺陷的编码，不能直接当作修正编码后的行为结论。

Llama 的 P1/P2 和闭卷置信度全部重新推理。Qwen 仅在全量 token ID 相同且模型权重 SHA256 重新核对一致后复用，manifest 明确标注来源、原执行脚本与复用依据，不声称是新的 Qwen GPU 推理。P2 的 Qwen 缓存仅在新的 P1 通过后导入。后续 P3/P4/P5 均需在新运行内重新验收。

本次 P1/P2 使用 GPU 1，FP32，预计显存 35–45 GiB；P1 15–30 分钟，通过后 P2 40–50 分钟。如继续至 P3/P4/P5，使用 GPU 0、1，每模型一张，样本仍为既定开发规模（P5 每模型 455 输入×16配置），分别预计 30–90 分钟、约30分钟、2–3小时。P6 不跨过前置关口或人工数据要求。

可复现证据：verify_tokenization.py、results/tokenization_audit.json、每模型逐提示指纹、results/qwen_reuse_weight_verification.json、results/freeze.json。编码修复不涉及修改金标、删除病例、重新抽样或放宽门槛。

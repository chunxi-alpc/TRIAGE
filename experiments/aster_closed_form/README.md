## 模型与三个模块

骨干为 `/home/gcx/TRIAGE/models/modelscope/Qwen3-8B`，冻结参数、BF16、关闭 thinking。固定“是／否”两个单词元，仅计算其 logit 差；大于零判“是”，同分判“否”。所有干预仅作用于最终判定位置、输出投影之前的查询头输出，共 36 层 × 32 查询头，即 1,152 个头。

- **M1**：A、P 分别归因，分别取 64 个候选，再以双向精确修补排序。总效应为右侧减左侧分数；反向修补分母为负总效应，归一化结果不裁剪。开发集测量固定排序的 0–64 头全部前缀，取联合恢复率达到 0.8 的最短前缀；未达标则取恢复率最高的最短前缀，允许空集并记录。最后保存两集合、并集及每头的干扰类型。
- **M2**：逐类型计算未中心化二阶矩，以能量目标选秩后再合并。每头仅纳入 M1 指定的 A/P 类型，同时保护 C/F。干扰效应阈值固定为 0.1，仅用于 M1 与 M2 干扰拟合；信号配对和主评测不据此筛选。参考均值使用未按效应筛选的全部拟合 A 配对两侧；A 为空时回退拟合原输入均值。
- **M3**：对 `(I − P_S) U_N` 做 SVD，按主夹角筛选方向，保存低秩因子 `N、B、mu`。在线依正常层序执行 `z − N @ B @ (z − mu)`，默认只擦除，无门控或放大。仅复用未编辑上下文缓存，每个节点直接评分一次，不额外计算盲读参考。

候选配置为能量目标 `{0.90, 0.95}` × 单类型秩上限 `{4, 8, 16}` × 夹角阈值 `{15°, 30°, 45°}`，共 18 组。合并维数可以超过单类型秩上限。开发集按四类配对正确率宏平均选择，并列依次比较原输入准确率、较少头、较低总编辑秩和较大夹角阈值。最终算子只由拟合数据估计。保存实际保留能量、零能量类型、舍弃方向及算子数值性质。

`operators.py` 提供：

```python
configuration_grid()  # 18 个 eta/kmax/theta 配置
fit_operators(features, pairs, heads, types, eta=.90, kmax=4, theta=15,
              variant="aster", anchor="paired")  # -> operators, diagnostics
layer_matched_random(heads, types, seed, heads_per_layer=32)  # -> heads, types
```

特征索引为 `view_id -> {ell, heads, ...}`，`heads` 形状为 `[层, 查询头, 头维数]`；配对包含来源、节点、划分、类型、两侧 ID、标签对应输入和编辑位置。原输入均值用特征中的 `original=True, split="fit"` 标记识别，兼容回退会在诊断中注明。

## 对照、机制与指标

行为对照包括完整阅读、提示忽略处置、直接遮挡、模型语义遮挡，以及使用构造标注的两种边界上限：保留指南定义且病历不变、另仅保留决定性患者事实。输出方法分别组合完整阅读与直接／语义遮挡，包含单路校准、概率平均、固定 logit 混合、`C=1` 的逻辑回归、标准 CAD 和反向适配。混合权重为 `{0, .25, .5, .75, 1}`，CAD 系数为 `{0, .25, .5, 1, 2, 4}`，均在开发集选择后固定。

标准 CAD 为 `(1+alpha)*full − alpha*masked`；反向适配为 `(1+alpha)*masked − alpha*full`。

H1 比较头数—联合恢复率曲线、同层同数量随机头（种子 13／37／73）和全部头修补。随机头同时保持每层 A-only、P-only、A/P 重叠数量，并重新估计后续算子。H2 保存主夹角和能量，并比较单头／联合子空间交换与完整头修补。H3 在拟合输入训练信号线性探针，于测试原模型错误样本评价；信号放大倍数在开发集从 `{1, 1.25, 1.5, 2}` 选择。

消融包括配对均值／原输入均值／零原点、逐类型均值差、去 C 或 F 保护、同方向正交擦除和 LEACE。均值差使用保存的配对朝向。LEACE 的概念编码为构造侧别与干扰类型／子类型，不使用节点真值；标准 LEACE 使用其概念拟合样本的经验均值，记录与 ASTER 配对均值的差异，其信号保持性质单独测量。所有模块替换重算后继产物。

开发和测试各固定 20 节点比较联合夹持下的局部预测、固定目标替换、实际逐层编辑。另计算完整／遮挡画像响应的差分之差，直接检验共享响应假设。

主表报告 `PA_A、PA_P、PA_C、PA_F`、宏平均、原输入准确率、纠错／退化、同节点双错纠正及分数响应。旧四输入全对率单列。全部有效测试配对进入主表；机制子集单列。区间按指南来源重采样。自主路径从根节点按各方法预测推进，不使用金标分支选择。PASTA、ITI、LoReFT、校准规模曲线和全面外部评测不属于本轮。

构造程序保留失败响应原文，重试时提供原患者、先前响应和具体错误。完整条件与祖先表达式通过后，缺少的 C 配对单独补充；显式数值比较可直接从已提取的事实与完整谓词计算可翻转阈值，同步修改条件及引用，再通过同一真值与祖先检查。修订保留历史记录与编号，已有有效配对继续复用。

## 服务器执行

所有准备、模型计算和测试均在 `gcx@10.29.128.115` 执行：

```bash
source /home/gcx/gcx261014/bin/activate
cd /home/gcx/TRIAGE-worktrees/aster-closed-form-20261105
python -m experiments.aster_closed_form --stage prepare
CUDA_VISIBLE_DEVICES=0,1 python -m experiments.aster_closed_form --stage all \
  --root /home/gcx/aster_closed_form_20261105
```

完整入口按阶段组织数据构造、特征缓存、A/P 选头、18 配置选择、消融、机制、路径和汇总；具体进展读取运行目录中的状态文件。独立阶段可用 `--stage` 指定 `construct、build、path-masks、collect、m1、fit-grid、grid、select、final、mechanisms、paths、report`。`--shard` 和 `--shards` 供内部多进程分工，单独启动 GPU 阶段时由 `CUDA_VISIBLE_DEVICES` 指定所分配的一张卡。不要在已有任务运行时重复启动相同阶段。

仅使用物理 GPU 0、1 两张 80GB A100。Qwen 每卡一份，初始显存估计 25–45 GiB／卡；MedGemma 补充构造与语义提取均在 GPU 0、1 各运行一份模型，按固定节点顺序分片，预计每卡 55–65 GiB。每个进程独立保存结果，阶段完成后归并，已完成记录直接复用；释放 MedGemma 后，两卡分别运行 Qwen。主数据最多约 2,000 个输入视图，另有定义与路径输入；双向修补、选参及消融初始预算约 8–12 万次末位置计算、8–16 小时纯运行。2026-11-05 改为双卡构造后，剩余时间暂估 10–14 小时。首批 20 节点计时用于更新估计，实际资源以运行记录为准。按用户要求，稳定后停止持续监控。

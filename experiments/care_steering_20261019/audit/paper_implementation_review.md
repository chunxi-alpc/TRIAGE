# 论文实现独立审查

审查对象：src/engine.py、src/run_facts.py。日期：2026-10-19。本审查不修改正在运行的脚本，不新开 GPU 实验；在服务器执行了隔离 CPU hook 单测，并核对已保存的源任务输出。代码 SHA-256 与机器可读证据见 paper_implementation_evidence.json。

## 结论

核心方向提取和残差干预符合论文描述：使用未归一化的均值差，在训练集按均值余弦选层，只修改指定层最后提示 token，生成后续 token 时不持续干预。没有发现此次结果需要因 hook 错误而重跑的证据。存在一项源任务评价代码缺口，但本次原始输出检查表明它没有改变 dev 系数选择。

这仍然是方法适配实验，不能称原论文原设置复现。主要差异包括源数据、改写方式、chat template、关闭 thinking、SDPA、生成上限、网格、评价人群和匹配器。

## 已核验

- engine.py:58–65 从每个 transformer block 的输出捕获最后 token，得到 resid_post；通过 hook 取值避免最后 hidden_state 已归一化的问题。
- run_facts.py:30–32 对严格合格 train 的 clean/conflict 激活分别求均值，方向为 c−f；没有单位长度归一化。只在 cos[:-1] 选最小值，排除最后 block。
- engine.py:35–46 仅当序列长度等于完整 prompt 长度时加增量，且只改 [:,-1,:]；generate 明确 use_cache=True。当前提示长度大于 1，所以缓存后的单 token decode 不会误触发。context manager 移除 hook。
- 单测以非单位向量 [3,4] 和 α=0.5 检查得到 [1.5,2]，证明未额外归一化；非末位置、decode 均不变。结果见 hook_cpu_unit_check.json。
- 已存源任务中 320 条有干预记录的输出均 calls=1、edited_positions=1、realized_delta_norm>0。BF16 加法未把增量全部舍入掉。
- train/dev/test 为 256/64/64，规范化问题无重复；11 个合格方向样本全部来自 train。dev 五个 α 各有 64 行，test 三种条件各有 64 行。
- 实际层为 31（从 0 计数）、方向范数约 229.64；这与当前训练集的几何准则一致。论文公布 Qwen3-8B 为层 21，但换源数据及提示后不能假定仍应固定为 21。
- dev 的 contextual-only 计数依次为 α=−3:47、−2:50、−1:49、−0.5:47、0:47，选择 −2。此处核对只用于检查既定选择过程，没有根据目标测试结果改超参。

## 发现与影响

### 源任务成功条件没有显式排除 both

run_facts.py:25 的训练 conflict 筛选、39–42 的 dev 目标仅检查修改答案命中。论文的 contextual-only 还要求不命中原答案，因此实现层面缺一项条件。若未来输出同时提到两答案，会把 both 计为正确，影响筛选或系数选择。

本次已保存的训练已接受 conflict、完整 dev 320 行、test 192 行均未出现两个答案同时命中的记录。离线按 context_match AND NOT parametric_match 重算仍选 −2，因此本次不必因这一问题重跑。建议最终统计始终报告四类匹配；未来运行前修正条件，但不要在运行中修改脚本。

### 匹配规则是预定的适配指标

run_facts.py:5–9 只保留 ASCII 字母数字，长度小于 4 的答案只接受整段规范化后完全一致；较长答案采用词边界包含。没有解析别名、移除起始冠词、语义蕴含判断，且无法识别“否定但提及答案”。

它与论文的标准化子串匹配并不完全相同。当前数据原答案长度小于 4 的 51 项、修改答案 55 项；这不是证明这些项判错，只说明严格整段相等规则影响范围不小。不得把该规则的准确率称语义正确率。原始输出可供复核；不要看 test 后选择更有利的判定规则。

### 其余已知适配与统计边界

- 5 个 clean 是指令包装，非 4 个独立语义改写；实际只有 11/256 train 样本合格。该方向的小样本稳定性未被重复训练或跨种子验证。
- max_new_tokens=24，与论文 200 不同。dev 有 2/320 条触及 24-token 上限；它们仍保留在分母。不能声称所有输出都自然结束。
- 源 dev/test 没有先按 clean 正确筛选，因此总体性能与论文 clean-known cohort 不同。source_test 保存了 prior_correct，可以另报预先说明的条件子集，不能替换主指标。
- 源 dev 的网格为 −3、−2、−1、−0.5、0，属稀疏预设网格；不能声称使用官方 0.2 步长完整扫描。
- engine.py:67–95 的 score 只在候选单 token 标签中选最大概率。患者任务若使用它，指标应标为受限选项判别结果；即使 raw_top_token 不是候选标签，也仍产生候选预测。它不能代表自由生成、指令格式遵循或自由文本临床建议的正确率。
- peak_memory_bytes 是模型进程累计峰值；未逐条件 reset，不能当各方法独立显存峰值。total_seconds 的 generate 部分不含 tokenization，score 部分包括候选标签编码，因此应按测量定义解释方法开销。

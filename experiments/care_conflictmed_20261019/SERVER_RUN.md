# CARE 医疗上下文冲突实测（2026-10-19）

已在 `gcx@10.29.128.115` 的 `gcx261014` 环境、GPU 0 上完成 Qwen3-8B BF16 实验。两轮共 **3,158 次实际生成**，没有使用本地 GPU。

本轮核实并取得 ConflictMedQA 的官方发布 [RDBH/DriftMed](https://huggingface.co/datasets/RDBH/DriftMed)，固定 revision `5dcfe380f49c6f17f3c6ba5e25e0e958f9642f0e`。实际包含 194 组建议和两版各 4,290 条场景；原生场景与建议行的映射尚未确认，因此本轮使用建议级适配，不冒称完整基准复现。

## 主要结果

严格已知标准为“两道无选项问题均正确，且两次候选换序均正确”。68 组测试事实中只有 **1 组**通过；在错误上下文下，无干预与校准方向均为 **0/2**。事后无选项补测同样均为 **0/2**。这证明了一个具体事实上的冲突行为，但样本不足以判断 CARE 有效性。

次要分析的 37 组“双换序已知”事实共 74 次回答：

| 方法 | 错误上下文下正确数 |
| --- | ---: |
| 无干预 | 10/74 |
| 验证集校准方向 | 11/74 |
| 提醒核查上下文 | 42/74 |

这些结果不能替代严格已知集，也不能当作 74 个独立事实。方向来自 37 组训练事实，第 27 层，验证集选择 `alpha=-2`。没有依据测试结果重选参数。

4 组患者条件反事实配对中，有上下文的无干预、固定方向、简化适用性门控均为 **10/16**。患者配对是适用性诊断，不计入参数知识冲突证据；门控是明确标注的手写条件解析，不是完整 CARE 模块。

## 复现

全部模型运行在服务器完成。先进入 `/home/gcx/gcx261014` 环境，模型目录由 `config.json` 指定。已有结果目录受到防覆盖检查保护；重跑应复制整个实验目录，并使用空的 `results/`、`logs/` 目录。

1. `python src/download.py` 获取固定版本原始数据；服务器外网不可达时，可在网络中转端下载后原样传入服务器。
2. `python src/prepare.py` 重建数据和配置。已有归档数据可直接使用。
3. 汇报 GPU、显存、规模和预计时长后，以 `bash run.sh` 运行主实验与分析。
4. 可选执行 `CUDA_VISIBLE_DEVICES=0 python src/run_open_context.py`，再执行 `python src/analyze.py`。此补测在本次实验中是事后探索性分析。

原始下载文件按发布数据卡标记为 Research Use Only，保留在服务器 `sources/`，未在此仓库重复上传。获取地址和 SHA256 可复核。派生实验材料用于研究。

未执行原生全量场景复现、真实历史指南更新验证、完整 CARE 模块一及键空间干预、多模型多种子、SFT/DPO 和独立临床专家复核。错误来源为人工构造文本，不应解释成真实过时指南或临床建议。

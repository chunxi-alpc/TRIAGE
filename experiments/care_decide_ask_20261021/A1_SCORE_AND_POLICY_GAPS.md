# 当前仓库的两处关键工程缺口

本目录不会伪装成已经完成冻结 A1 的保形校准。2026-10-21 核查 GitHub 主分支：`configs/care_module1_for_module2.json` 与 `experiments/care_module1_semantic_v8/export_a1_signals.py` **只包含离散 T/F/U（或技术失败 null）**，明确 `confidence_threshold: null`、`confidence_or_evidence_gate: false`，没有三状态概率。

## 缺口 A：A1 没有 T/F/U 概率

保形方法需要每条规则在同一固定评分协议下的 `p(T), p(F), p(U)` 或其他单调、可重复的不一致分数。**不能把 `T` 人为赋成 `0.99`、把 `F/U` 赋成 `0.005`，更不能把 Qwen 的动作选项 logits 当作 A1 的规则状态概率。**

建议的两条分开路径：

1. **立即可做、无统计保证：** 原封不动使用已保存冻结 A1 硬标签（T 单集合、F 单集合、U/null 全状态集合），加上可执行规则传播。用于性能基线与错误传播分析，指标标记 `uncalibrated`；风险无法用 α 约束。
2. **额外评分实验：** 固定同一 Phi-4+TrialMatchAI 权重、冻结提示及示例，另行实现每条规则 T/F/U 的严格条件评分（对 JSON 结构/词元位置进行合法的序列概率计算），独立校验评分与原始 A1 硬预测之间的一致性、解析异常和长度效应，再输出 `rule_probs` 与 `score_provenance`。这是**新模型前向与新接口**，不是现成 A1 概率；必须另列版本、计算成本、哈希和失败率。校准之前冻结评分方法，不用 test 选温度、示例或打分位置。

校准格式示例（仅示意，不是现有模型输出）：

```json
{
  "family_id":"new-mechanism-family-01",
  "truth":{"R1":"T","R2":"U"},
  "probs":{"R1":{"T":0.7,"F":0.2,"U":0.1},"R2":{"T":0.1,"F":0.1,"U":0.8}}
}
```

评分缺失时 `None` → 全状态集合；若评分总和异常或没有可信来源，`care_decide_ask.a1_adapter.require_a1_probabilities` **必须拒绝**，不能声明保形保证。

## 缺口 B：自由文本规则还不是可执行决策政策

当前 A1 能给规则 ID 及其适用性分类，并不自动给出：

- 可独立询问的患者**属性**（与某条规则 ID 不等价）；
- 规则文本的逻辑条件与否定、括号、优先级；
- 多规则相互约束、覆盖、排斥、版本和适用范围；
- 默认动作、保守升级/人工审查政策。

本目录的 `core.py` 只支持 **布尔谓词条件、and/or/not、显式优先级、可选一致性约束**，最多 18 个原子谓词（超出拒绝枚举），数值比较必须在独立经审查的抽象层编译为布尔谓词。新基准可用手写/程序生成的 DSL 当 oracle；真实指南需要另一个独立验证的结构化政策输入，这会成为系统的一项明确成本。

**不要为了跑通而让 LLM 从规则正文自动生成 DSL 后不验证就作为 gold。** 可以引入人审核、双人复核与差异审计；错误编译时，本论文的动作风险保证不适用。

## 与主仓库共存而不改 A1

当前开发路线在 `experiments/care_decide_ask_20261021/` 单独建立原型，旧 `src/module1/` 和 PR #17 N1–N5 结果保持不变。后续 A1 适配只允许读取 `case_id/rule_id` 和冻结状态及方法出处，严格按原始规则文本、政策版本和 SHA 匹配，不调用推断 gold 筛例。

仓库目前为 GitHub **public** 可见；真实患者资料、受限临床文件或评审未授权输入不可直接上传。只提交合成小样本与 hash/许可记录。

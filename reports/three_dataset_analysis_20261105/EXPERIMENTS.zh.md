## MedPAIR：删除与补回

历史删除对照使用 Full（完整证据）、High（全部高相关句，旧 TOP1）、Low（删除全部高相关句，旧 NO_TOP1）及已保存的句数/长度匹配随机子集。报告 A=Acc(Full)−Acc(当前条件)、正确答案分数差、Full 正确而当前条件错误的比例。随机对照先在每题内平均现有种子。

补回子集需同时有高相关句与明确不相关句。每题根据原标签和模型 tokenizer 的 token 长度，选择长度差最小的一对原句 h、u；并列依次按高相关句、不相关句的原顺序选择。共同底稿 C=Full−{h,u}。比较 C、C+h、C+u，两种补回均放在被删除句子中较早的原位置，其他原句、顺序、句子编号和选项保持一致。

新增评分使用 Qwen3-8B base、bfloat16、原纯文本提示与带前导空格的选项字母 token，不使用聊天模板或 adapter。每次调用原 score_answer_choices 完成一次前向，同时保存所有候选的原始 logits 和归一化分数。仅在有效选项内归一化并取最高分；相同提示与候选集合直接复用。

Full/High 共 360 条条件记录，补回共 180 条，合计 540 条；去重后为 538 次评分。20 道开发题的 55 次试跑已计入。GPU 0/1 分别完成剩余 241/242 次，峰值预留显存约 16.05/16.46 GiB，含加载时间约 18.31/66.46 秒；试跑约 9.66 秒、15.70 GiB。进程均已退出。

历史 High 为 56/89，本轮为 55/89；Full 均为 60/89。历史删除对照与本轮完整选项融合分别呈现，旧文件不足以判定差异原因。

## MedGUIDE：方案交换与规则阈值变化

方案可见输入含患者、条件、分支编号及处置文字；遮挡输入保留相同患者、条件和编号，删除处置文字。两路回答相同的分支选择问题，候选集合和正确答案一致。

A 为原始处置，B/C/D 为已有处置交换变体。逐一比较 A→B、A→C、A→D 的预测改变、正确变错误、错误变正确。A/B/C/D 的遮挡提示及分数相同，基础错误率只计 A 一次。

规则阈值变化测试使用 84 组 A→CS：患者文本不变，规则阈值和正确分支改变。报告遮挡条件下的配对失误、预测不变和新旧正确分支分数变化。该项单列，名称不改为患者事实变化。

## MedEinst：关键事实响应

使用 M3A 的 46 候选序列总 log p，每侧独立取最高分；不使用旧文件中强制两侧诊断不同的 predicted_transition。三个模型分别报告。设原侧与变化侧预测为 ŷc、ŷt，正确答案为 yc、yt：

- 配对失误率 P_b：至少一侧错误的病例对数 / 病例对数。
- 预测不变率：ŷc=ŷt 的病例对数 / 病例对数。
- 原侧正确、变化侧坚持原诊断：ŷc=yc 且 ŷt=yc 的病例对数 / 全部病例对数。
- 分数支持增量 Δ=[st(yt)−st(yc)]−[sc(yt)−sc(yc)]；报告 Δ>0 比例和中位数。
- 另报两侧准确率、全部单例错误，以及分数方向改善但变化侧仍错的比例。

候选 token 均值评分、M1 两诊断评分、Work3 自由生成结果均单列补充。

## 输出融合

MedPAIR 使用 Full/High，MedGUIDE 使用可见/遮挡。仅融合问题、答案和候选集合相同的两路输入。MedEinst 的两侧正确诊断不同，不参与融合。

| 方法 | 定义和开发集选择 |
|---|---|
| 概率平均 | p=w pF+(1−w)pM；w∈{0,0.25,0.5,0.75,1}，按开发准确率选择，并列取较大 w |
| CAD_full | s=(1+α)log pF−α log pM；α∈{0,0.25,0.5,1,2,4}，并列取较小 α |
| CAD_masked | 交换两路，使用同一 α 网格 |
| 学习式融合 | s=wF log pF+wM log pM；最小化开发集候选 softmax 平均负对数似然+0.01(wF²+wM²)，两权重允许为负 |

两个数据集分别选参，测试固定参数。MedGUIDE 开发集先对每病例的现有变体平均，再对病例平均，共 149 例、593 个变体。测试按 A/B/C/D/CS 分别报告。

B=两路均错数/测试样本数；双错纠正率=融合纠正的双错数/两路均错数；损害率=至少一路正确却被融合判错数/至少一路正确数。另报损害数/全部测试样本，并区分两路同一错误答案与不同错误答案。损害率不是相对 Full 新增错误率。

选出的概率平均 w 均为 0.5，两种 CAD 的 α 均为 0。学习式权重为 MedPAIR (0.329539, 0.251039)、MedGUIDE (0.174117, 0.151485)，完整精度及开发网格结果见[参数文件](../../results/three_dataset_analysis_20261105/README.md)。

## 统计、验证与复现

差值采用种子 42、2,000 次配对 bootstrap：MedPAIR 按题、MedEinst 按病例对、MedGUIDE 按指南树重采样。MedGUIDE 主估计仍按病例计算，重采样以树为单位。CS 仅一棵树，跨树区间为空；额外提供该树内按病例对重采样的补充区间。

已有验证通过：选项映射与概率归一化、配对输入、开发/测试分组、相同位置补回、融合计数关系；4 项融合测试覆盖零系数、相同分数、双错为空、不同候选数及概率平均纠正不同错误等情况。

在服务器激活环境后，进入[代码目录](../../experiments/three_dataset_analysis_20261105/README.md)。分析依赖 NumPy/SciPy；模型评分另依赖原仓库及 PyTorch/Transformers。代码绑定本次服务器目录和 inventory。顺序为：

1. analyze_offline.py：复算已有结果。
2. prepare_medpair.py：准备补评分输入；score_medpair.py：仅在缺少分数且已汇报 GPU 资源时运行，断点只补缺失记录。
3. analyze_medpair.py、make_report.py：生成完整汇总。
4. python -m unittest test_analysis、verify_results.py：必要验证。
5. export_repository.py：将已有汇总结果整理到仓库，不启动推理。

本次仓库整理只执行最后一步及文档链接检查。原始文件位置、固定划分、输入和逐条分数见[服务器文件索引](../../results/three_dataset_analysis_20261105/artifact_locations.json)。

# E1 表示基线补拟合准备

已读取 Codex 01 的对应审计结论，不重复审计其他方法。本目录只完成运行准备和 SEA 未解释回退的 CPU 诊断；尚未运行 E1 基线拟合或 GPU 推理。

| 方法 | 已有结果 | 本轮处理 |
|---|---|---|
| ITI-style task adaptation | 历史完整评价保留 | 按 E1 全部端点重新估计正确/错误答案方向与头探针，保持现有目标 |
| LEACE-pair adaptation | 历史完整评价保留 | 调用原 fit_operators 的 leace 分支；明确共享冻结 E1 头位置及配对侧监督 |
| SEA task adaptation | 历史完整评价和共同指标已存在 | 保留已有结果；解释回退后，若开展 E1 比较才按原谱目标重拟合 |
| 标准 LEACE | 不由现有配对侧标签代表 | 需要稳定实例概念标签，交由新增擦除任务处理，不臆造标签 |

固定输入是原 E1 缓存中的 2,540 对、4,637 个唯一端点、80 个来源。所有训练端点均取自 E1；已有普通激活直接读取缓存。ITI/SEA 的正确及错误答案完成激活优先复用旧缓存，仅对缺失端点做额外前向。没有 ASTER 差分损失或证据约束损失，也没有重新训练 ASTER。

LEACE-pair 复用冻结 E1 的51个头位置，属于共享 ASTER 头定位监督的任务适配比较；不称作标准原生 LEACE。现有 leace 拟合入口自身保留 A/P 原始分数差的 0.1 过滤规则。本轮向其传入完整2,540对，不额外增加筛选。

执行入口为 `experiments/aster_e5_gaps_20261112/e1_representation_baselines.py`。在服务器激活 `/home/gcx/gcx261014` 后，从工作树根目录运行：

- `--mode prepare`：已完成数据及设置说明。
- `--mode fit-leace`：仅 CPU，读取已有 E1 特征，输出 `leace_pair/operator.pt`。
- `--mode extract-truth --device cuda:0`：取得缺失的正确/错误完成激活；必须等待允许使用的GPU释放并完成资源汇报，当前未启动。
- `--mode fit-iti`：仅 CPU，使用完成激活缓存，输出 `iti_style/operator.pt`。
- `--mode fit-sea`：仅 CPU，调用已有 `sea_basis`，输出 `sea_adaptation/operator.pt`。
- `--mode diagnose-sea --limit 32`：已完成，原始记录见 `sea_fallback_diagnostic.json`。

提取和拟合是分开的，已有产物不覆盖。正确/错误头激活缓存约5.5GB，ITI临时数组约另5.5GB。LEACE不需要新的主干前向；ITI/SEA最坏需要4,637×2次答案完成前向，实际扣除旧缓存。后续开发/测试推理应继续复用 `Comparators.edited` 原钩子，并限制为目标方法，不调用会同时拟合其他方法的旧总入口。

本轮参数冻结为历史设置：ITI强度15、51头、逻辑探针C=1；SEA谱能量0.998；LEACE原固定配置。没有用历史测试结果重新选择参数。确定性闭式/探针结果不伪造三种子波动。

SEA诊断发现：官方类把单词元输入转成4096×1，再沿长度/批次轴对每个坐标归一化。BF16正负投影和在某坐标抵消为0时出现0/0，旧钩子只恢复这些坐标的原值。计数代表非有限标量坐标，不是样本数。32个已有开发样本复现55个非有限坐标，同时32个样本均有真实表示改动，不能把SEA说成完全未生效。

当前原目录四个开发分片计数分别为2300、2444、2358、2376；四个测试分片为4652、4581、4578、4566。审计引用的4744不能代替此完整范围。CPU与GPU BF16矩阵乘数值可能不同，历史运行未保存精确回退坐标，因此本诊断没有宣称逐个复现全部历史回退位置。未改SEA归一化方式、未重跑完整评价；历史结果按任务适配版并注明回退策略保留。

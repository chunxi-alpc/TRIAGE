# 保持相同分数的计算加速

用户于2026-11-17要求提高效率。先保存112,126条已完成的匹配对照分数，再进行独立的GPU实现核验。所有已提交SQLite记录均保留并复用。

原实现每次修补一个头都重新计算36个解码层。本批请求平均干预层编号24.97，平均只需重算后11.03层。本实现为每个目标输入执行一次原生基线，缓存各层输入、注意力头输出和位置/掩码参数；每次修补仅替换对应头，重算该层输出投影和MLP，再执行全部后续层与最终归一化、FP32标签投影。数据、供体、头、阈值、数值容差、精度、注意力实现及统计方法保持不变。

GPU 0核验覆盖3个训练输入长度（实际请求中的最短、中位、最长）和86个修补/自身替换条件。原完整计算与新实现的标量分数逐项完全一致，最大绝对差为0。记录见equivalence_records.json。86项完整计算耗时2.149秒，新实现0.743秒，前向加速2.894倍；峰值分配显存18.01 GiB。核验产生的额外前向属于实现检查，未作为独立科学证据或混入对照统计。

实现版本：8602059d。四卡生产运行已恢复，按首批实际速度，每卡约105.4—111.8条新分数/秒；本次观察估计剩余GPU时间约1.72小时，后续CPU分析另计。该估计随输入长度和修补层位置变化。四卡状态和峰值显存见production_verified.json。

统一队列当前只运行PR #82的新M1任务。PR #81原实验及其后续模型保持用户请求的暂停状态，恢复信息见prior_experiment_pause.json。
